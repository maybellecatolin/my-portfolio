# Maybelle Catolin · Portfolio

Personal portfolio of Maybelle Catolin, a senior software engineer building secure, accessible web and mobile products with React, React Native and TypeScript.

A single-page home (hero, work, recommendations, experience, toolkit, contact) plus a case study page for each project. Every page is statically generated.

## Stack

- [Next.js 16](https://nextjs.org) App Router, fully static output
- React 19 and TypeScript (strict)
- [Motion](https://motion.dev) for scroll reveals and transitions, loaded through `LazyMotion`
- CSS Modules, with a small global layer in `app/globals.css` (Tailwind CSS 4 is wired into the PostCSS pipeline)
- ESLint (`next/core-web-vitals` and TypeScript rules)

## Getting started

Requires Node.js 20.11 or later.

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Commands

| Command         | What it does                                                        |
| --------------- | ------------------------------------------------------------------- |
| `npm run dev`   | Start the development server                                        |
| `npm run build` | Create the production build (type-checks and prerenders every page) |
| `npm run start` | Serve the production build                                          |
| `npm run lint`  | Run ESLint                                                          |
| `npm run og`    | Regenerate the social preview images in `public/og/` (needs Chrome) |

## Project structure

```text
app/
  layout.tsx               Root layout and site-wide metadata (Open Graph, Twitter, robots)
  page.tsx                 Home page + Person/WebSite structured data
  projects/[slug]/page.tsx Case study pages + per-project metadata and structured data
  not-found.tsx            Custom 404
  sitemap.ts, robots.ts    Generated sitemap.xml and robots.txt
  globals.css              Design tokens and shared global styles
components/common/         Shared primitives (Reveal, DarkSheet, MotionProvider, SectionKicker)
features/portfolio/
  data.ts                  Home page content: contact, nav, stats, career, recommendations, toolkit
  projects.ts              Case study content and carousel images
  site.ts                  Site identity and URL for metadata, sitemap and structured data
  components/              One component (and CSS Module) per section
  hooks/                   Scroll-spy hooks (active section, active project)
public/
  projects/<slug>/         Carousel images (01.webp, 02.webp, …; 16:10 works best)
  og/                      Social preview images (generated by `npm run og`)
  hero/, brand/, badges/   Hero illustration layers, logo, store badges
scripts/
  generate-og-images.mjs   Renders the social preview images with headless Chrome
```

Components are server components by default. Only the pieces that need the browser are client components: animation wrappers, the carousel, the scroll-driven showcase and timeline, the header's scroll state and mobile menu, and the recommendation cards.

## Updating content

- **Home page text**: `features/portfolio/data.ts`.
- **Projects**: `features/portfolio/projects.ts`. Each project has:
  - `summary` (Work list) and `tagline` (case study subtitle)
  - `images`: files in `public/projects/<slug>/`, numbered from `01.webp`. Use `fit: "contain"` (and optionally `background`) for portrait phone screens.
  - Optional `link` (website), `stores` (App Store / Google Play badges), `socials` (Instagram / Facebook) and `disclaimer` (shown for work under NDA, on the case study and in the Work list).
- **After changing a project's name, industry, tagline or first slide**, run `npm run og` so its social preview matches.
- **Replacing an image with the same file name while `npm run dev` is running**: delete `.next/cache/images`, then hard-refresh, or you'll keep seeing the cached version.

Screens for projects under NDA are illustrative mockups, labelled as such on the image, in the caption and in a disclaimer.

## SEO and sharing

- Titles use a template (`<page> | Maybelle Catolin`), with a unique description and canonical URL per page.
- Open Graph and Twitter card tags on every page, with a 1200×630 preview image per page.
- JSON-LD structured data: `WebSite` and `Person` on the home page, `CreativeWork` and `BreadcrumbList` on each case study.
- `sitemap.xml` (with image entries) and `robots.txt` are generated at build time.
- The 404 page is excluded from indexing.

## Analytics

Google Analytics 4 loads when `NEXT_PUBLIC_GA_ID` is set, and only in production builds, so local development never sends data.

- **Page views** are recorded automatically, including client-side navigation. In GA, keep Enhanced Measurement's "Page changes based on browser history events" option on.
- **Clicks**: any element with `data-track="event_name"` sends that event, and its `data-track-*` attributes become parameters (see `components/common/Analytics.tsx`). Events in use:

| Event                  | Parameters            | Sent from                                                   |
| ---------------------- | --------------------- | ----------------------------------------------------------- |
| `nav_click`            | `section`, `location` | Header and mobile menu links                                |
| `cta_click`            | `label`               | "View my work", 404 page buttons                            |
| `contact_click`        | `method`, `location`  | Email, LinkedIn and "Request CV" links                      |
| `project_open`         | `project`, `location` | Work list, carousel images, Experience rows, project pager  |
| `store_click`          | `store`, `project`    | App Store / Google Play badges                              |
| `social_click`         | `network`, `project`  | Instagram / Facebook links                                  |
| `website_click`        | `project`             | Project website links                                       |
| `recommendation_click` | `person`              | Recommender name links                                      |

To break reports down by these parameters, register them in GA under **Admin → Custom definitions → Custom dimensions** (event scope): `section`, `location`, `label`, `method`, `project`, `store`, `network`, `person`.

## Deployment

The site builds to static pages and deploys anywhere that runs Next.js. [Vercel](https://vercel.com) needs no configuration.

1. Import the repository in Vercel.
2. Set the environment variables (see `.env.example`):
   - `NEXT_PUBLIC_SITE_URL`: your domain, e.g. `https://maybellecatolin.com`. This drives canonical links, social previews and the sitemap. Without it, Vercel's production domain is used.
   - `NEXT_PUBLIC_GA_ID`: your GA4 measurement ID (`G-…`), to turn on analytics.
3. Deploy. After going live, check a link preview with LinkedIn's [Post Inspector](https://www.linkedin.com/post-inspector/) and submit `/sitemap.xml` in Google Search Console.

## Performance and accessibility notes

- Images go through `next/image` (responsive sizes, lazy loading, modern formats). Only the images visible on first paint are preloaded: the hero's main layers, plus the first slide of the first carousel on the page.
- Motion loads only the features in use (`LazyMotion` + `m` components, in strict mode), and every animation respects the visitor's reduced-motion setting.
- Carousels autoplay only while on screen, pause on hover or keyboard focus, and stop for good once the visitor swipes or uses an arrow or dot.
- System fonts only, so there are no web-font downloads or layout shift.
- Semantic landmarks, one `h1` per page, a skip link, visible focus styles, keyboard-accessible menu (native `<dialog>`) and carousel controls.
